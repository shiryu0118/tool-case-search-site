# 要件書

## 概要

Flask製の「ツール活用事例検索サイト」を開発します。このサイトは、Zenn・Qiita・はてなブログからツール名で記事を検索し、判定結果をGoogleスプレッドシートまたはSQLiteに保存する機能を提供します。

## 要件

### 要件 1

**ユーザーストーリー:** 開発者として、ツール名を入力して関連記事を検索したいので、複数のプラットフォームから効率的に情報収集できる

#### 受入基準

1. WHEN ユーザーがツール名を入力して検索ボタンを押す THEN システムは Zenn、Qiita、はてなブログから関連記事を検索する
2. WHEN 検索が完了する THEN システムは検索結果を一覧表示する
3. WHEN 検索結果が表示される THEN 各記事のタイトル、URL、プラットフォーム名、公開日が表示される
4. IF 検索結果が0件の場合 THEN システムは「該当する記事が見つかりませんでした」というメッセージを表示する

### 要件 2

**ユーザーストーリー:** システム管理者として、検索結果を永続化したいので、データの保存と後での分析が可能になる

#### 受入基準

1. WHEN 検索が実行される THEN システムは検索結果をSQLiteデータベースに保存する
2. WHEN SQLiteへの保存が成功する THEN システムは同時にGoogleスプレッドシートへの保存を試行する（オプション）
3. WHEN データを保存する THEN システムは検索キーワード、記事タイトル、URL、プラットフォーム、公開日、検索実行日時を記録する
4. IF Googleスプレッドシートへの保存が失敗しても THEN システムはSQLiteの保存が成功していれば処理を継続する

### 要件 3

**ユーザーストーリー:** 開発者として、過去の検索履歴を確認したいので、以前に検索したツールの情報を再確認できる

#### 受入基準

1. WHEN ユーザーが検索履歴ページにアクセスする THEN システムは過去の検索結果を日時順で表示する
2. WHEN 検索履歴を表示する THEN 各エントリに検索キーワード、検索日時、見つかった記事数を表示する
3. WHEN 検索履歴の特定のエントリをクリックする THEN システムはその検索の詳細結果を表示する
4. IF 検索履歴が存在しない場合 THEN システムは「検索履歴がありません」というメッセージを表示する

### 要件 4

**ユーザーストーリー:** システム管理者として、APIレート制限を考慮したい効率的な検索を実装したいので、サービスの安定性を確保できる

#### 受入基準

1. WHEN 外部APIを呼び出す THEN システムは1時間のキャッシュを適用する
2. WHEN 同じ検索クエリが短時間で実行される THEN システムはキャッシュされた結果を返す
3. WHEN APIレート制限に達する THEN システムは適切な待機時間を設けて再試行する
4. IF 外部APIが利用できない場合 THEN システムはエラーメッセージを表示して他のプラットフォームの検索を継続する

### 要件 5

**ユーザーストーリー:** 開発者として、本番環境とローカル環境で同じアプリケーションを動作させたいので、環境に応じた設定管理ができる

#### 受入基準

1. WHEN アプリケーションが起動する THEN システムは環境変数から設定を読み込む
2. WHEN ローカル環境で実行する THEN システムは.envファイルから設定を読み込む
3. WHEN 本番環境（Render）で実行する THEN システムは環境変数から設定を読み込む
4. IF 必要な環境変数が設定されていない場合 THEN システムはデフォルト値を使用するかエラーメッセージを表示する

### 要件 6

**ユーザーストーリー:** 開発チームとして、コードの品質を維持したいので、自動的なコード整形とCI/CDパイプラインを利用できる

#### 受入基準

1. WHEN コードがコミットされる THEN システムはBlackとisortでコードを自動整形する
2. WHEN mainブランチにプッシュされる THEN GitHub Actionsが自動的にRenderにデプロイする
3. WHEN デプロイが実行される THEN システムは必要な環境変数とシークレットを使用する
4. IF デプロイが失敗する THEN システムは適切なエラーメッセージを出力する
